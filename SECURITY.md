# Security Policy — Invoice Next

## Overview

Invoice Next is an online invoicing platform for freelancers and small businesses. We are committed to maintaining the security, reliability, and integrity of our website, application, and software dependencies.

## Supported Versions

| Version / Branch | Security Support |
|---|---|
| Latest maintained `main` branch | Supported |
| Current production release | Supported |
| Active development branches | Maintained during development |
| Older, unmaintained releases | Not supported |

Security updates are prioritized for the current production release and actively maintained code.

## Reporting a Vulnerability

If you discover a potential security vulnerability in Invoice Next, please report it privately to the project maintainers.

**Security Contact:** shabir3875@gmail.com


Please include:

- A clear description of the vulnerability.
- The affected page, feature, API, or component.
- Steps to reproduce the issue.
- The potential security impact.
- Relevant screenshots or logs, without exposing sensitive information.
- Any suggested remediation.

**Please do not publicly disclose vulnerabilities or publish sensitive proof-of-concept details before the maintainers have had an opportunity to investigate.**

## Security Review Process

Reported vulnerabilities will be:

1. Reviewed and assessed for validity.
2. Classified according to severity and potential impact.
3. Investigated to determine the root cause.
4. Remediated through appropriate code or dependency updates.
5. Tested before release.
6. Documented and communicated as appropriate.

Response and remediation timelines depend on severity, complexity, and available resources.

## Dependency Security

Invoice Next uses automated and manual security checks, including:

- npm dependency auditing.
- Dependabot alerts and updates, where enabled.
- Code review and security regression testing.
- Compatibility and production build testing.
- Review of custom or modified third-party packages.

A clean dependency audit does not guarantee that all application vulnerabilities have been eliminated.

## Responsible Disclosure

We appreciate responsible security research.

Please avoid:

- Accessing or exposing other users' information.
- Modifying or deleting production data.
- Disrupting the availability of the service.
- Testing real payment transactions without authorization.
- Sharing credentials, tokens, or confidential information.

## Security Updates

Confirmed security fixes are tested and released through the project's established development, review, and deployment process.

Production deployments require appropriate approval.
